# 価値創生の翼 — 施策案への反応を分解して比べる

生成したセグメントに複数の施策案をぶつけ、反応を分解して案を比較する。
TOPPANを追い越す軸は人数ではなく、**客に示せる信頼度**。
設計の全体像は `claude/design/value-creation-wing.md`（プロジェクト）にある。

ファイル（この翼の新規分）:

| ファイル | 役割 |
|---|---|
| `reaction.py` | 価格受容・反応分解・複数案比較の本体 |
| `proposals_sample.json` | 外食の施策案3案（サンプル） |

土台として再利用：`population.py`（セグメント生成）、`attributes.json`＋`cross_engine.py`（家計調査の金額）。

---

## 考え方

購入意向をLLMに直接聞かない。シリコン・サンプリングの分散過少と偏りがそのまま出るため。
代わりに、**価格受容を家計調査で接地**し、それを主たる説明変数にした透明な式で出す。
反応を4つに割り、それぞれに信頼度タグを付ける。

- 価格受容：接地。家計調査の品目月額に対する施策案価格の倍率から出す。
- 購入意向：価格受容（接地）×便益適合（既定1.0・方向性のみ）。
- 反応理由：任意のLLMフック。APIキーが無くても核は動く。
- 確信度：便益適合を動かした分だけ下がる。

---

## 使い方

### 価格受容だけ見る

```powershell
python reaction.py accept --item 外食 --price 16000
```

同じ16,000円でも、年収I層には4.2倍で「かなり高い」、V層には0.9倍で「妥当」と出る。
倍率と判定は家計調査由来（接地）。受容スコアは倍率から出す単調減少のモデル曲線。

### セグメントに複数案をぶつける

```powershell
python reaction.py run --frame 全国 --n 500 --proposals proposals_sample.json
python reaction.py run --frame 沖縄県 --n 300 --proposals proposals_sample.json
python reaction.py run --frame 全国 --n 300 --where has_child=あり --proposals proposals_sample.json
```

出力は、案の順位（平均購入意向）、1位案の価格受容の分布、分散過少の自己点検、信頼度タグ。

---

## 施策案の書き方

`proposals_sample.json` の形。価格は想定月額（円/月）に正規化する。
家計調査の品目月額と同じ土俵で比べるため。1回いくらの施策は、想定利用頻度を掛けて月額にする。

```json
{
  "cross_item": "外食",
  "proposals": [
    {"id":"A","name":"平日ランチ定額","price_monthly":6000,
     "benefit":"平日の昼を固定費化","message":"...","benefit_fit":1.0}
  ]
}
```

`benefit_fit` は便益がそのセグメントにどれだけ響くかの係数（0.5〜1.5、既定1.0）。
1.0から動かすのは方向性のみの判断で、接地ではない。動かすと購入意向のタグが
「接地＋方向性」に変わり、確信度が下がる。ここを隠して動かすと、数字の信頼度が偽装される。

## 整合性チェック（数字が元データの含意どおりか）

翼の出力が、土台の1次データから当然そうなるはずの関係を保っているかを自動検査する。

```powershell
python sanity_check.py
```

5項目を検査する。教育の対象外率が国勢調査の子なし率と一致するか（83.0%対82.9%）、
価格が高い案ほど価格受容が低いか、年収別でV層>I層か、高所得県≧低所得県か、
深掘り生成が目標人数に届くか。全合格で終了コード0。
施策案やデータを変えたあとに回すと、接地が崩れていないか確かめられる。

## 題材を自分で足す

`proposals_TEMPLATE.json` をコピーして編集すれば、新しい施策案を足せる。
`cross_item` を家計調査の品目名にし、価格を想定月額にするだけ。駆動軸は自動で選ばれる。

## 読み方と限界

**価格受容は接地、案の順位は方向性のみ。** 順位は価格だけで並んでいて、
便益の差はまだ入っていない。便益適合を動かせば順位は変わるが、その動かし方に
接地の裏づけはない。だから順位をそのまま「どの案が勝つか」の結論にしない。

**態度の外的妥当性（実人間との一致）は未検証。** 外部調査の照合（`benchmark_survey.py`）が
済むまで、購入意向の水準は実人間と一致する保証がない。
用途は本調査前の仮説出しと足切りに限る。案の優劣をそのまま意思決定に使わない。

**分散過少の自己点検。** 価格受容は五分位で変わるはずなので、ばらつきがほぼ無ければ警告を出す。
これは入力やモデルの異常を捕まえる保険で、外的妥当性の保証ではない。

## 題材カタログ（接地できる施策案のサンプル）

家計調査で金額が取れている品目のうち、接地できる6カテゴリの施策案サンプルを用意した。
`--proposals` に渡すだけで、複数案比較・接地ターゲティングが動く。

| ファイル | 品目 | 駆動軸 | 例 |
|---|---|---|---|
| `proposals_sample.json` | 外食 | 所得 | 平日ランチ定額 / 週末ディナー / デリバリー |
| `proposals_leisure`（※都度作成） | 教養娯楽 | 所得 | サブスク束ね / 趣味体験 |
| `proposals_apparel.json` | 被服及び履物 | 所得 | 洋服サブスク / スタイリスト付き |
| `proposals_mobility.json` | 交通・通信 | 所得 | 格安モバイル / 通信＋移動パック |
| `proposals_homegoods.json` | 家具・家事用品 | 所得 | 日用品定期便 / 家具レンタル |
| `proposals_education.json` | 教育 | 子の有無 | オンライン学習 / 個別指導 |

所得駆動の5カテゴリは年収軸で接地、教育は子の有無で接地する（子なしは対象外）。
新しい題材を足すときは、`cross_item` を家計調査の品目名（attributes.json にあるもの）にし、
価格は想定月額に正規化する。品目の駆動軸は reaction.py が自動で選ぶ。

保健医療（世帯主年齢で駆動）は run では参考値。`accept --item 保健医療 --axis age` で見る。

## 接地ターゲティング（誰に当てるか）

便益の仮定を一切使わず、家計調査の価格受容だけで、1施策案の当てやすさをセグメント間で比べる。
完全に接地なので、狙う層の答えに方向性の濁りが入らない。TOPPANの方向性のみの反応にはできない出し方。

```powershell
python reaction.py target --proposals proposals_sample.json --id B --by income_quintile
python reaction.py target --proposals proposals_sample.json --id B --by prefecture
```

外食の週末ディナー（16,000円）なら、V層は平均価格受容58%・無理ない層100%、I層は18%・0%と、
狙うべき層がデータで出る。

## 品目ごとの接地の限界（重要）

価格受容は家計調査の「年収別」テーブルで接地している。これが正しいのは**所得で決まる品目**だけ。

- 所得駆動（接地が有効）：外食、教養娯楽、被服、交通・通信、交際費、こづかい
- 構成駆動（年収だけでは歪む）：教育（子の有無）、保健医療（世帯主年齢）

教育費は本来子の有無で決まるのに、年収別テーブルは子あり世帯の高い教育費を
年収V層全体に広げてしまう。だから子なし高所得にも高い教育費があるように接地され、
子有無でのターゲティングがほぼ差を出さない。`reaction.py` はこの品目に「注意」を出す。

### 第2軸（世帯主年齢）で接地できる

構成駆動の品目には、世帯主年齢を代理軸にした家計調査の金額表（2024、総世帯）を足した。
年齢は子育て期を捉えるので、教育の構造がくっきり出る。

```powershell
python reaction.py accept --item 教育 --axis age --price 8000
python reaction.py accept --item 保健医療 --axis age --price 5000
```

教育の月8,000円は、世帯主40-49歳（月22,037円使う子育て期）には「安い寄り」、
29歳以下・70歳以上（ほぼ0）には「かなり高い／対象外」と出る。所得軸では出ない構造。
品目を指定すると軸は自動選択される（教育・保健医療は年齢軸、外食などは年収軸）。

### 教育は run / target でも本接地（子の有無で接地）

教育は、年齢階級別の金額（子育て期40-50代＝月約2万円）を基準額の錨にし、
ペルソナが持つ `has_child`（国勢調査ベース）で接地する。
子なし世帯は教育費がほぼ0なので「対象外」として母集団から外す。

```powershell
python reaction.py run --frame 全国 --n 500 --proposals proposals_education.json
python reaction.py target --proposals proposals_education.json --id E2 --by has_child
```

run は「子あり世帯のみ対象」と明示し、対象外（子なし）の割合を別に出す。
target を has_child で見ると、子あり17%が無理ない層100%、子なし83%は対象外0%と、
狙う層が接地でそのまま出る。

保健医療は駆動要因が世帯主年齢で、ペルソナに年齢がまだ無いため、
run では年収軸の参考値のまま。正しい見方は `accept --item 保健医療 --axis age`。
年齢を run に統合するには世帯主年齢の分布が要るが、令和7国勢調査では
細かい年齢階級の世帯分布がまだ公表されておらず、信頼できる新しい分布が取れていないため次段。

## 次にやると効くこと

1. 品目を増やす：家計調査にある品目（教養娯楽・教育・保健医療など）を `cross_item` に指定すれば、そのまま接地できる。
2. 便益適合を接地する：いまは方向性のみ。セグメントの心理項目（新商品関心など）を外部調査で照合してから便益適合に反映すれば、順位も方向性から接地に近づく。
3. 反応理由のLLMフック：APIキーを設定し、接地した価格受容・バンドを渡して理由文を書かせる。固有名は `grounding_check.py` で創作と印づけする。
