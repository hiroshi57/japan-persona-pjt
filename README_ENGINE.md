# 属性クロス基盤

任意の属性どうしをクロスして、同時出現率・条件付き分布・金額推計を、
実データに裏づけて出すエンジン。都道府県×子供×ペットは、この基盤の一例にすぎない。

ファイルは2つ。

| ファイル | 役割 |
|---|---|
| `attributes.json` | 属性の周辺分布と、属性どうしの関係（条件付き分布・金額表）の登録簿 |
| `cross_engine.py` | 登録簿を読んでクロスを解くエンジン |

---

## 2つの原則

**1. 独立とみなして掛け算しない。**
関係が登録されていればそれを使い、無ければ独立を仮定したうえで「独立仮定を使った」と結果に必ず明示する。前のペット例で、全国平均を単純に3つ掛けると実際より25%低く出たのは、この独立仮定の誤りだった。

**2. 裏づけの出どころを全部残す。**
クロスは「因子」の積で表され、因子ごとに1次データ／2次データ／推計／独立仮定のどれかが付く。結果を見れば、どこが固く、どこが推測なのかが一目でわかる。

---

## 4つの問い方

### 同時出現率 — occurrence

条件をすべて満たす世帯の割合。`P(A かつ B かつ C)` を連鎖で解く。

```powershell
python cross_engine.py occurrence --where has_child=あり household_size=2 pet=犬
```

`P(子あり) × P(2人世帯) × P(犬 | 2人世帯)` のように、条件付き関係があればそれを使う。household_size と has_child の関係が未登録なら、その因子だけ「独立仮定」と表示される。どこを埋めれば精度が上がるかがそのまま出る。

### 条件付き分布 — conditional

ある属性を固定したときの、別の属性の分布。

```powershell
python cross_engine.py conditional --target pet --where household_size=1
```

単身世帯なら犬4.77%・猫5.87%・なし89.36%、と返る。2人以上世帯とは別の分布になる。

### 金額・数量の推計 — metric

品目を世帯属性でクロスした推計値。これが会話の金額・数量を裏づける核。

```powershell
python cross_engine.py metric --item 外食 --where income_quintile=V
```

年収V層（860万円〜）の外食は月17,127円、I層（〜329万円）は3,821円、と家計調査の実数が返る。

### 裏づけの限界 — ground / map

その属性がどの粒度まで裏づけられるか。

```powershell
python cross_engine.py ground 店名
python cross_engine.py map
```

## 会話の属性をどう扱うか

ご要望の商品名・店名・地名・時期・数量・金額は、裏づけの限界が属性ごとに違う。
エンジンはこの線を機械的に引く。

| 会話の属性 | 裏づけられる粒度 | 出どころ | 固有名 |
|---|---|---|---|
| 金額 | 品目×世帯属性の平均月額 | 家計調査（1次） | — |
| 数量 | 一部品目の年間購入数量 | 家計調査（1次） | — |
| 品目 | 家計調査の品目分類 | 家計調査（1次） | — |
| 時期 | 月別の支出指数 | 家計調査 月次（1次） | — |
| 地域 | 都道府県・市区町村・都市階級 | 国勢調査・家計調査（1次） | — |
| 業態 | スーパー／コンビニ／百貨店／通販 | 家計調査・経済センサス（1次） | — |
| **店名** | **業態まで。固有名は不可** | **該当なし** | **創作** |
| **商品名** | **品目まで。ブランドは不可** | **該当なし** | **創作** |
| **地名** | **市区町村まで。駅名・商店街は不可** | **該当なし** | **創作** |

ここが最も重要な結論。**固有名詞は、どの公的統計にも大規模調査にも存在しない。**
「イオンでルンバを7万円」のうち、

- 「7万円」相当の金額水準は、年収階級と品目から裏づけられる
- 「ルンバ」は品目（調理家電・掃除機）までしか裏づけられず、ブランドは創作
- 「イオン」は業態（総合スーパー）までしか裏づけられず、店名は創作
- 「新宿」は市区町村までで、固有の地名は創作

つまりクロスで固められるのは**カテゴリと金額水準まで**。固有名はそこから先、依然として言語モデルの創作であり、前に作った裏づけ判定器（grounding_check.py）が引いた線とちょうど一致する。

## ペルソナ生成・会話への つなぎ方

このエンジンは、生成と会話の両方に効く。

**生成側**: `generation_core.py` が属性を引くとき、独立に引くのではなく、
このエンジンの conditional を使えば、関係を保ったまま引ける。
ペット飼育率を世帯人員で条件づける、金額を年収で条件づける、といった形。

**会話側**: ペルソナに金額や品目を言わせる前に、metric を引いて
「この年収なら外食は月1.2万円前後」という水準を渡す。
言語モデルに数字を創作させる代わりに、データ由来の中心値を与え、
その周りで散らす。固有名（店名・商品名）は創作のままだが、
grounding_check.py が印をつけるので、事実として引用される事故は防げる。

## 登録簿の育て方

`attributes.json` は、使いながら関係を足していく前提で作ってある。

- **金額の品目を増やす**: `metric:金額|income_quintile` の items に、
  e-Stat の家計調査から品目の月額を転記する。ペット関連費・保健医療・交通なども同じ表にある。
- **関係を足す**: `has_child|income_quintile` のように table が null の関係は、
  埋めるまで独立仮定として扱われる。国勢調査や家計調査のクロス集計から table を入れると、
  occurrence の「独立仮定」表示がひとつ消える。
- **新しい属性を足す**: attributes に marginal と tier と source と groundability を書く。
  固有名詞なら proper_noun は false のままにし、level をカテゴリ止まりにする。

推測値は入れない。関係が無いなら table を null のままにして、
エンジンに「独立仮定」と言わせる。そのほうが、誤差の所在がはっきりする。

## 現在の登録状況

- 金額（年収×品目）: 家計調査2020年値で12品目（消費支出・食料・外食・住居・光熱水道・家具家事用品・被服・保健医療・交通通信・教育・教養娯楽・その他／交際費・こづかい）。10大費目を網羅し、各列が消費支出と一致。1次データ。
- ペット（世帯人員×犬猫）: ペットフード協会2024年。2次データ。
- 子あり率・世帯人員・年収五分位の周辺分布: 国勢調査・家計調査。1次データ。
- 都市階級・時期・業態・数量: 枠だけ用意。e-Stat から実数を転記して有効化する。
- 店名・商品名・地名: 固有名は裏づけ不能と登録済み（埋める対象ではない）。

家計調査の金額は2020年値が入っている。より新しい年次がe-Statにあるので、
運用前に差し替えること。差し替え方は `metric:金額|income_quintile` の source に書いてある。
